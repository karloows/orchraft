# Issue Format

Use this as the fallback issue shape when the target project has no issue
template. A target project's template, labels, issue types, and custom fields
always take priority.

## Title

Use a concise, technical title that states the problem or requested outcome.

## Body

### Summary

Describe the actual problem or requested outcome.

### Reproduction

For bugs, list the smallest reliable steps to reproduce the problem. Omit
this section for feature requests or when reproduction steps are unavailable.

### Expected Behavior

What should happen.

### Actual Behavior

What happens now. Omit this section for feature requests.

### Acceptance Criteria

Use only criteria supplied by the user or the repository's conventions. Omit
this section when none were provided.

### Notes

Optional logs, links, screenshots, constraints, or related context.
